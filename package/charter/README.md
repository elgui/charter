# charter/

The written charter of this project. Machines check it; people own it.

| File | What it is | Who changes it |
|---|---|---|
| `scope.md` | What is sold, what is not, the assumptions. Summarised from the signed devis | The owner |
| `decisions/<slug>.md` | One design decision per file. Code cites it with `charter:<slug>` | Whoever settles it; status by the owner |
| `decisions/INDEX.md` | Generated by `charter decisions index` | Nobody |
| `changes/<slug>.md` | A change request for work outside the scope | Anyone proposes; only the owner approves |
| `config.json` | Track (`client` or `prototype`), owner, limits, probes, price estimates per model. A key, type or track the gates do not know is refused at commit; `python3 .charter/bin/charter config` lists what is read | The owner |
| `legacy-taskets.txt` | Taskets found at install without an acceptance section; the done gate lets them close with a warning | Written by the installer; entries removed by anyone, added by the owner |
| `ledger.jsonl` | Tokens and estimated cost per session and unit | `charter ledger` |
| `progress.md` | Generated by `charter synth --write` | Nobody |
| `templates/` | Templates for the files above and for a unit of work | The package |
| `VERSION` | Installed package version | The installer |

Units of work live in `.taskets/` (see `templates/unit.md`). Tooling lives in `.charter/`. The gate log and session records live in the git directory (`.git/charter/`), shared by worktrees and never committed.

Each clone activates the git hook once with `python3 .charter/bin/charter setup`; git does not clone it.

Owner-only: `scope.md`, `rails.md`, `config.json`, adding an id to `legacy-taskets.txt`, the approval fields of change requests, the status of existing decisions and the `check:` and `binds:` of active ones, opening or widening a `kind: split` unit, `.charter/`, `.claude/settings.json`, `.claude/settings.local.json` and `.github/workflows/charter.yml`. The full list is in `.claude/rules/charter.md`. An agent's Edit or Write on them is refused unless Claude Code was started with `CHARTER_OWNER=1`, and so is a commit of them made from inside Claude Code. The owner commits them; an agent stages them and runs `python3 .charter/bin/charter handover`, which prints the owner's one line (`charter owner commit`, 0.4.12). An upgrade's package files, exactly as the installer wrote them (their hashes match `.charter/manifest.json`), are the exception: an agent commits those.

The owner's delegate (0.4.14): where `delegate.level` in the config committed on the default branch is `routine`, `answers` or `open`, a watcher outside Claude Code takes some of these acts for the owner after rules and an independent model judge them, and hands the rest back. `strict`, the default, takes nothing. `python3 .charter/bin/charter delegate level` prints the level; only the owner sets it. What each level takes, and what the agent does, is in `.claude/rules/charter.md` § The owner's delegate.
