1. What a project carries

A small written charter: the scope summarised from the signed devis, one file per design decision, change requests for anything outside the scope, and units of work (taskets) that cite them. Machines check it; the owner owns it.

2. The life of a unit

One unit, from planned to costed. The top band runs inside a Claude Code session; the bottom band holds for any agent or person, because it runs in the git hook and in CI.

3. Three layers, one set of checks

Four gates are hard everywhere they run: scope, size, done and decisions. The fifth, anchored deliverables, is hard in CI. The owner-only checks guard the files that define all five. Everything else warns and is logged.

7. What the trial and the review showed

What 0.2.0 changed, by finding of the review:

  1. Frontmatter comments read as YAML reads them; templates keep comments on their own lines, which tcv2 needs.
  2. CI compares against the base: a file that grew is refused, only units closing in the change set are judged, an unusable base checks everything.
  3. A fresh clone gets its git hook from charter setup or the installer; the banner says when it is missing.
  4. Owner-only files and fields: refused to Edit and Write, blocked at commit inside Claude Code, checked against the author in CI.
  5. Evidence must name a commit or a run; probes can be re-run; changing criteria mid-flight needs a log line.
  6. CI fetches pull-request heads; the synthesis labels a squashed commit historical.
  7. The gate log lives in the git directory, shared by worktrees; CHARTER_UNIT wins.
  8. Acceptance is read when the synthesis runs; prices per model, 1-hour cache writes, rework, human minutes.
  9. The scope parser tolerates headings and says what makes it fail open.
  10. Taskets found at install close with a warning; every later one is gated.
  11. The Stop gate judges only turns that changed something, and wants a commit, path:line or run.
  12. The PR body is checked as a warning, #123 counts, and edits re-run it.
  13. The pre-commit judges the index, not the working tree.
  14. A check: stays shell from markdown: the feature (L8).

8. What remains architectural

What no code in the repository can remove, each marked where it occurs in the figures above. Most of these are held in place by the fact that one person runs the agents on their own machine.

  • L1 · where: PreToolUse owner-only check; pre-commit · finding 4

    One machine, one identity

    The agent runs on the owner's machine, with the owner's filesystem and git identity. A Bash command (sed -i, cat >) is not an Edit or a Write, so PreToolUse never sees it. A commit made in Bash is authored as the owner. Prefixing CHARTER_OWNER=1 to a git commit in Bash passes the pre-commit's owner check; the forgery is visible in the transcript, not prevented.

    What reduces it: Nothing inside the repository. Outside it: a separate machine account for agents, or signed commits that the agent cannot produce.

  • L2 · where: CI · finding 4, 14

    A pull request can edit its own judge

    GitHub runs the workflow and the gate code as they are in the pull request. CI refuses owner-only changes from an author who is not owner and gate code that differs from .charter/manifest.json, but a pull request can rewrite those checks in the same change.

    What reduces it: GitHub branch protection with required review from code owners on charter/, .charter/ and .github/workflows/: the one lock a pull request cannot edit.

  • L3 · where: Acceptance probes; the done gate · finding 5

    The agent writes its own probes

    The done gate can require a named commit or a recorded run, and with probes enabled it re-runs them. It cannot judge whether a probe tests what the criterion says: probe: `true` passes, and so does a test that asserts nothing.

    What reduces it: The charter-reviewer agent or the owner reads the probes. Criteria changed after work starts need a log line, so weakening them is visible.

  • L4 · where: Merge; the CI done gate · finding 6

    Squash outside a hosted pull request

    An evidence SHA names a commit on the branch. A squash or rebase merge removes that commit from the history. CI fetches refs/pull/*/head, which GitHub keeps, so a merge made through a pull request still resolves. A squash made locally and pushed leaves nothing to fetch: CI blocks the push that closes the unit, and the synthesis labels the SHA historical.

    What reduces it: A merge-commit policy recorded as a charter decision, which the migration guide asks client projects to write (Path A step 5).

  • L5 · where: CI runner; engine worktrees · finding 7

    State that leaves the repository

    The gate log lives in the git directory, shared by worktrees. A CI runner is thrown away after each job, and its log with it. Engines get the perimeter gate and a unit-attributed ledger only if they export CHARTER_UNIT to the sessions they start; that change belongs to tele-claude and tcv2.

    What reduces it: Engine follow-ups (listed in the evaluation). Uploading CI logs as artifacts is possible but outside this package.

  • L6 · where: SessionEnd; the ledger · finding 8

    One session, one unit

    SessionEnd sums the whole transcript and records it against the unit active at the end. A session that moved between units is misattributed.

    What reduces it: Logging unit start and stop times and matching them against the transcript's timestamps. Not built.

  • L7 · where: The scope gate · finding 9

    Path globs cannot see intent

    The scope gate matches paths. Where in-scope work and an upsell share files, it cannot tell them apart (the orqueveaux audit names one such file).

    What reduces it: The unit's scope: and the owner's review carry it; the change request remains the written place for it.

  • L8 · where: The decision gate · finding 14

    check: is shell from markdown

    A decision's check: is a shell command read from a markdown file and run by the hooks, the pre-commit and CI. CI already runs a pull request's own code through its tests, so this adds no new capability to someone who can open one.

    What reduces it: The SessionStart banner lists every check:; changing one on an active decision is owner-only.

  • L9 · where: Pre-commit · finding 3

    The git hook is advisory for whoever skips it

    git commit --no-verify skips the hook, and a clone gets no hook until charter setup runs (the banner says so). CI runs the same checks; nothing records the skip itself.

    What reduces it: CI on every pull request and push to the protected branches.
