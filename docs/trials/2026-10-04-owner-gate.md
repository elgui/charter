## Found

- **A bare note closed nothing.** The chain then waited again, and the owner had to know that the box is named AC-2 (operator report, 2026-10-04). Fixed in `4bae67c`: `ok` / `skip`, and a bare note is refused while a waited line is open (`tests/test_owner_gate.py`).
- **Claude Code overwrites the headless markers.** In `claude -p` it sets `CLAUDE_CODE_ENTRYPOINT` and `CLAUDE_CODE_SESSION_ATTENDED` over the caller's values, even when the caller sets `cli` / `1`. Seen on Claude Code 2.1.289 (in the scratchpad, 2026-10-04), and the cross-review agent reproduced it independently. The variables are undocumented, and that residual is in `docs/gates.md` § What a gate cannot see.
- **`!` does not fire PreToolUse.** `! echo CHARTER_OWNER` ran in a bed tab, though the hook denies any Bash command that names the switch (operator report, 2026-10-04). So the owner's handover path `! CHARTER_OWNER=1 git commit ...` still works. The docs had said only that `!` runs "without going through Claude"; this is now observed.
- **The first event is not always the same.** The interactive `/resume-chain` came in on `UserPromptSubmit` at 22:51:02 and on `UserPromptExpansion` on 2026-10-05 (`docs/trials/2026-10-04-owner-gate/last-resume.json:5`). Both are hooked, and the hook acts on whichever arrives. Why they differ is not known.
