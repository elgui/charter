Asked to “tick AC-10 yourself”?

Reply: “Locate the exact project, branch, tasket file and criterion. Check the Owner Desk and any existing approval. Give me the desk item, the action and the expected result.”

AC-10 is a checkbox label inside one tasket, not a global identifier. You should receive enough context to act without searching for Markdown.

Three places, three jobs

Project + Charter
What are we delivering?
Taskets, criteria, probes, decisions and gates.
→
Tele-Claude
Where is the work running?
Cards, sessions, tasket board, automation and checker.
→
Owner Desk
What needs me now?
Decisions, prepared actions and observations.

The same tasket can appear in both systems. A tasket id identifies work; an oa-… id identifies a desk ask. Neither completion automatically proves the other.

Work through an agent

  1. Choose: “Show the road and recommend the next unit.” Charter’s next reads the plan and open work.
  2. Prepare: “Write acceptance criteria and probes, then start the unit.” The tasket lives in .taskets/.
  3. Build: the agent works within the perimeter, records evidence and commits on a branch.
  4. Finish: “Run the probes; show what passed, what remains and what needs me.” Open owner criteria keep the unit open.

Ask separately: “Is it recorded done, tested, reviewed, deployed, or observed in use?” Those are different claims.

Clear what needs you

Open the project’s Owner Desk invitation in Tele-Claude, or the global desk for all projects.

  • Decide: read the question, consequences and recommendation; choose or give your own answer.
  • Do: inspect the prepared action; run it through the desk. Prompts and logins use the owner terminal.
  • Check: follow the location/setup instructions. Pass means you observed the expected result. Unfinished observation stays open.

If instructions or context are missing, ask the agent to prepare them before you act.

Current gap: answering can leave the box open

A desk Check records your observation and attempts a tasket Log commit; it does not itself tick the acceptance box. Some acceptance decisions also record an answer without closing the line. Ask the agent to trace the receipt and identify the supported owner/delegate completion path. A previous approval should be inspected before another is requested.

For now: require the exact file, branch, criterion and remaining act. An owner line stays protected; the proposed automatic connection is not implemented by this sheet.

The contract: Charter’s installed owner --json → desk detector → ask → your action → outcome/log. Owner items are derived where possible; agents file only uncovered present needs. A generic desk receipt is not a guarantee that a protected source box changed.

Inspect before repairing

In the target project’s terminal, where Charter is installed. These read state:

python3 .charter/bin/charter config
python3 .charter/bin/charter next
python3 .charter/bin/charter owner --json
python3 .charter/bin/charter unit show ID --json

Replace ID with the tasket id from next or its file. The unit JSON includes its path, acceptance lines and done blockers. Charter’s source repository itself has no installed project CLI.

Desk terminal commands: owner list, owner show oa-ID, owner mine. Here owner means Tele-Claude’s scripts/owner; use its full path if the shortcut is absent. Replace oa-ID with a listed ask id.

Charter owner lists repository obligations. Tele-Claude owner reads the cross-project desk. They are different commands.

Keep the right layer current

  1. Inspect versions: in the Charter checkout, run python3 bin/charter-pkg status /path/to/project. fleet lists projects and versions.
  2. Upgrade a project: ask the agent to follow docs/install.md § Upgrade: clean isolated tree, branch, intervening release notes, dry run, then upgrade. The installer says who commits.
  3. Check the machine layer: python3 bin/charter-pkg machine status. Links into a checkout can make edits live immediately.
  4. Update Tele-Claude separately: a Charter upgrade does not deploy the backend or rebuild the dashboard. Check desk restart/build asks.

Changing this source checkout does not upgrade installed projects. Preserve project edits; resolve KEEP reports before overwriting.

Delegation and stalled work

charter delegate plan reads what the delegate may take. Levels: strict none; routine eligible probe checks/upgrades; answers also transcribes your answers; open also eligible road/scope edits and merges. Restrictions still apply.

A waiting package chain resumes through your /resume-chain prompt in interactive Claude Code. Desk completion alone does not resume it. For stale taskets/asks, request “housekeep this project’s taskets and Owner Desk.”

When filing a methodology bug

Give the agent: project + branch + tasket path/id + AC label + desk id/receipt + expected result. Ask it to compare the source item, exported JSON, desk item and resulting commit.

Missing export or gate/verb behavior → Charter. Missing discovery, instructions, approval handling or receipt → Tele-Claude. A broken connection → both, with one explicit contract. Gates, tests, review and deployment need separate evidence.
