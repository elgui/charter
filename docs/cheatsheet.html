Charter & Tele-Claude at your desk

Choose the work · follow its evidence · settle what needs you

Charter package 0.4.21
Reviewed 3 November 2026
Installed versions vary by project.

Charter: the repository’s work record, rules and protected commits.

Tele-Claude: cards, sessions, tasket board, automation and checker.

Owner Desk, inside Tele-Claude: decisions, prepared actions and checks. Your confirmation goes back to Charter.

What to say to the agent

Pick unit → write criteria → build → verify → record. Open owner criteria keep the unit open.
  • Start: “Show the road and recommend the next unit.”
  • Prepare: “Write acceptance criteria and probes; start the unit.”
  • Finish: “Show the evidence, remaining work and Owner Desk items.”

A unit is one deliverable in .taskets/. Its perimeter limits edits; its probes test its criteria. A decision lives in charter/decisions/; rails are the project’s planned road.

Your daily pass through the desk

Open the project’s Owner Desk invitation for that project, or the global desk for all projects.

  • Decide: compare the options and recommendation; give your answer.
  • Do: inspect and run the prepared action. Prompts, passwords and logins use the owner terminal.
  • Check: follow the setup and observe the expected result. Pass records success; unfinished observation stays open.

For a supported Charter acceptance card, Pass also commits that specific criterion and its receipt. A refusal keeps the ask open with the error.

A tasket id identifies work. An oa-… id identifies a desk ask. One tasket can need several asks; one restart can serve several taskets.

Inspect the target project

In its terminal, from the root where Charter is installed. These read state.

python3 .charter/bin/charter next
python3 .charter/bin/charter owner --json
python3 .charter/bin/charter unit show ID --json
python3 .charter/bin/charter config

Get ID from next or the tasket file. unit show gives its path, criteria and done blockers. The Charter source repository itself is not an installed project.

When a request says only “tick AC-10”

Reply: “Locate the project, branch, tasket and criterion. Check existing approvals. Give me the corresponding desk item and expected result.”

AC-10 is a label inside one tasket. You should not have to search for its Markdown file. Missing instructions are preparation work for the agent.

Ask what was established: recorded done · probes passed · reviewed · deployed · observed in use. Each needs its own evidence.

2 / Maintenance & troubleshooting

Follow the boundary before changing anything

Charter defines and protects acceptance.
The desk delivers your confirmation.
Deployment makes that code usable.

The approval path — and where to investigate

Source criterion → Charter export → desk card → you confirm → Charter commits the tick and receipt. Source/gate/export: Charter. Discovery/presentation/confirmation: Tele-Claude. A failed write leaves the request open.

Four layers to keep current

Available package: Charter checkout; changing it does not upgrade projects.

Project installation: upgrade through docs/install.md on a clean branch.

Machine layer: shared skill/hook; linked edits may be live.

Deployment: running Tele-Claude backend and served dashboard need separate updates.

Maintenance you can request

  • “Compare installed Charter versions and prepare the needed upgrades.”
  • “Housekeep this project’s taskets and Owner Desk.” This reviews their relationship; it does not perform your approvals.
  • “Check what is committed, running and served before proposing a restart or deploy.”

From a checkout containing the intended Charter release:
python3 bin/charter-pkg status /path/to/project
python3 bin/charter-pkg fleet
python3 bin/charter-pkg machine status

If something does not close

Absent / unclear askCompare Charter’s export with the desk record; prepare missing context.
Old installationPrepare Charter 0.4.21+ and deploy desk support. An old receipt is not replayed automatically.
Pass refusedRead the error. Refresh the source/card; resolve changed text, branch or dirty target.
Chain still waitsThe package chain needs your /resume-chain prompt in interactive Claude Code.

Authority and useful identifiers

Keep project + branch + tasket path/id + AC label + desk id/receipt together when reporting a problem.

Charter owner reads repository obligations. Tele-Claude scripts/owner reads the desk: list, show oa-ID, mine. Replace oa-ID with the actual listed ask.

Delegate levels: strict: none; routine: eligible probe checks/upgrades; answers: also transcribes your answers; open: also eligible road/scope edits and merges. charter delegate plan reads eligible work. Only the owner changes the level; config and structural changes stay protected.
